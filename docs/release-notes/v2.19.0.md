## 摘要
這一版是程式碼審查後的修正版：自動打牌的「過」、斷線處理與局間確認卡住提示，協議橋接的寶牌、重連回音、加槓與錄影，以及雲端退化顯示與 MCP `kan` 參數檢查。修正都只有離線單元測試，沒有 live 對局驗證。

## 變更
### 修正
- 自動打牌：斷線時「過」不再空轉重試，改交給既有的離線延後。單測已驗；斷線重連未 live 驗證
- 自動打牌：「過」與其他動作使用同一套成功判準，必須收到同 msgId 的回應且沒有 error 才算成功。單測已驗；段位場送出未 live 驗證
- 自動確認：局間確認卡住時，側欄會出現停滯提示。單測已驗；畫面未 live 驗證
- 雲端推論：貼上的 key 或 URL 帶換行或空白時，會先清掉再使用，不再變成 401。單測已驗；雲端伺服器實際收到的標頭未驗證
- 協議橋接：槓之後新增的寶牌不再被吞；快照路徑與事件路徑對寶牌的處理一致。單測已驗；槓寶牌顯示未 live 驗證
- 協議橋接：重連重放的歷史動作不再被當成自家回音。單測已驗；重連封包形狀未 live 驗證
- 協議橋接：加槓的 consumed 取自實際的碰，不再一律推定含赤五。單測已驗；未 live 驗證
- 協議橋接：送出前就確定失敗的封包不再佔著 msgId 登記；失敗原因不明時仍保留登記。單測已驗；段位場 sid 未 live 驗證
- 對局錄影：不再留下他人暱稱。單測已驗；實際錄影檔內容未 live 驗證
- 側欄：異常列與展開層對「改用本機」使用同一個判準，連續非雲端決策數大於 0 就顯示。單測已驗；側欄實際畫面未 live 驗證
- 除錯伺服器：重啟一律從偏好 port 8765 開始；工具列與設定頁仍顯示實際綁到的 port。單測已驗；port 被佔用後重啟未 live 驗證
- MCP：`kan` 指令給了無法辨識的 `kanType` 或 tile（例如空字串）時，回傳錯誤、不送出封包；`kanType`、tile 給 null 時視同沒給，照常推導。單測已驗；MCP 客戶端實際收到的錯誤訊息未驗證

### 行為變更
- 內部：高亮推薦腳本抽成 `WebSession.recommendationScript`，移除不再被產品呼叫的 `GameHighlightScript.make`。使用者看不到差異；腳本發布結果有單測鎖定，live 推薦發布未驗證
- 內部：新增 8 條測試，鎖定插件只改自家 authGame 外觀時，Naki 的座位、玩家數與事件流不變

## 已知限制
- 本版所有修正只有離線單元測試，沒有 live 對局驗證
- 真實 authGame 封包形狀，以及 syncGame、enterGame 重連封包，未驗證
- 已知待處理的審查項目（BR-06、BR-02、BT-05、SV-07、BT-20）不在本版範圍
- 未簽名：首次開啟要在系統設定放行；IPA 需自行簽名側載
