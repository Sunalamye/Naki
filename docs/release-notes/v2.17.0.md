## 摘要
這版是一輪設計重審的收斂：吃牌對照失敗、和牌無授權時改為不送，吃牌三選一的選擇會帶到執行器，座位欄位缺席改補 0 並記故障，插件的 `isNaki` 語意也改了，其餘為內部清理。

## 變更

### 修正
- 吃牌時，雀魂的組合對照不到推薦時改為不送、不消化操作清單：只有恰好一組才退回第一組，多組或零組都不送，不再猜一組而可能吃錯牌
- 吃牌有多種組合時，推薦文字裡的吃牌變體一路帶到執行器，不再固定使用第一組（live 已驗）
- 自動打牌收到和牌建議，但伺服器沒有授權和牌時，不再送出自摸（正式流程下不可達，未在 live 驗證）
- 雲端回傳的吃牌若牌字串不是合法的 MJAI 寫法，改為退回本地決策，不再照單全收
- 換局或重連時取消推論，不再被記成雲端故障：斷路器不會被誤開、接下來幾手不會被白白擋回本地，畫面也不再誤顯示降級；立直第二段取消同理
- 換局之後才回來的舊局錯誤，不再被寫成新局的 Bot 失敗訊息
- `oauth2Auth` 回應不再被當成登入回應解析，避免 access token 的首位元組被誤認為帳號 ID 而認錯座位
- 登入回應的帳號欄位型別不符時不再採用，改記降級故障
- 連線建立時的狀態重置改為同步執行，遊戲在連線後立刻送出的請求，回應不會再因為重置而配不上並靜默遺失
- 在不支援自動送出的裝置切換模式時，「此裝置不支援自動送出」的提示不再被緊接的狀態訊息蓋掉
- 傳統路徑下 `bot_trigger` 不再回報 `queued: true`，改回 `legacy_path_action_send_disabled`，因為該路徑實際不會送出
- 偵錯伺服器所有埠都綁定失敗之後可以重新啟動，不再永遠回報「已在運行」
- iOS 版頁面載入失敗時補上常駐提示橫幅
- `sendRaw` 在送出模組缺席時回短碼 `no_websocket_module`，不再丟出自由文字的 `js_error`
- 頁面自己送出、msgId 達 60000 以上的請求，不再被誤認成 Naki 送出的流量
- 插件看到的 msgId 超過 31 位元時不再算錯

### 行為變更
- 伺服器封包缺少座位欄位或吃碰槓的類型欄位時，視為 0 並記一筆降級故障，不再丟棄事件；型別錯誤或超出範圍仍丟棄並記故障。缺類型欄位補成吃的前提是四人局，且打出的牌與消耗的牌為三張同花色連號
- 回應配不到先前請求時，原本只有追蹤級 log，現在記資訊級 log 並附累計次數，同時記一筆降級故障（不觸發橫幅）
- 三麻本地授權序號與事件序號不一致時，新增一行 Bot log
- 插件 API：`ctx.isNaki` 符號不變，語意改為「Naki 自己送出的訊息（`sendRaw` 登記表）加上插件保留的 msgId 區間 64000 至 65500」；頁面 API 新增 `__nakiWebSocket.isNakiSent(msgId)`
- 插件匯入的 manifest 驗證規則不變，錯誤訊息較以往長
- 移除 `lobby_start_match`、`lobby_cancel_match`、`lobby_match_modes`（2026-08-09 起伺服器一律回 error 1306，2026-10-13 再次實測），MCP 工具數由 43 個降為 40 個；現行入口是 `lobby_start_unified_match`
- 測試不再寫入使用者的真實設定檔
- 內部：Swift 6 警告歸零、移除約一千行死碼與無人使用的預設參數，並把吃牌變體、和牌與槓種的退路、自動打牌放行判斷各收成單一規則
- 內部：CLAUDE.md、AUDIT.md、三語 README 與插件 API v1 文件對齊現況，三個無引用的本地化字串刪除

## 已知限制
- 四麻友人房一局（PC 對手）已驗自動打牌、榮和、自摸、吃牌三選一與局間確認；三麻、段位場與真人對手未驗
- 座位或類型欄位缺席補 0：四麻一局未觸發（伺服器明送 seat=0，降級故障 0 筆）；三麻未驗，若伺服器省略欄位但語意不是 0，座位會錯記且畫面看不出，降級故障是唯一訊號
- 同類多組槓仍一律送第一組，加槓的 index 與 tile 仍未帶（本次 live 無槓樣本）
- `isNaki` 的登記表只保留最近 256 筆：Naki 送出後又經 `sendRaw` 送出 256 筆以上並全部往返完成，那筆回應才到時，`isNaki` 會變成 false，違反 v1 文件「Naki 流量永不給 rewrite」；上限無單元測試鎖住，溢出未實測
- 繞過 `sendRaw` 直接呼叫 `ws.send` 的送出會被當成遊戲流量，目前只有手動 `execute_js` 會走到
- 重連時三麻回應配不到請求的 log 量級未在 live 驗證，可能每次重連多出數十行資訊級 log
