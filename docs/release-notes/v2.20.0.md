## 摘要
這一版讓插件能整包替換或丟棄收到的訊息，並加入大廳請求的送出守衛；同時修正對局結束後誤報協定改變、連線失敗後殘留連線紀錄等問題。

## 變更
### 新功能
- 插件：收到的訊息可以用長度不同的內容整包替換。manifest 的 `capabilities` 要同時宣告 `rewriteReceive` 與 `reshapeReceive`，`ctx.replace` 才會換掉整包；沒宣告的插件行為與舊版相同
- 插件：新增 `ctx.drop()`（`dropReceive`），可丟棄收到的 NOTIFY，遊戲與 Naki 都不會收到；需要開啟 L3 總開關
- 插件：牌局、登入、匹配相關的訊息在禁改名單內，不能整包替換或丟棄；改寫後交付失敗時，這個頁面停用整包替換與丟棄，重新載入頁面才恢復，遊戲與自動打牌照常
- 插件：新增送出守衛。插件在 manifest 以 `sendGuard` 宣告要守的大廳方法，改寫過之後，這些請求到頁面重新載入前都不會原樣送出，即使插件被停用也一樣
- 插件頁：詳情顯示插件的來源網址，手動安裝的顯示「手動安裝」；macOS 可在 Finder 中顯示插件資料夾

### 修正
- 對局結束後不再誤報「雀魂改了協定欄位」。伺服器拒絕客戶端重送的對局驗證時，Naki 只記錄錯誤碼
- 遊戲頁內的 WebSocket 連線失敗、只觸發錯誤沒有關閉事件時，連線紀錄也會清掉，插件看到的連線清單不再殘留已斷的連線
- Naki 自送請求的辨識改以「連線加 msgId」判斷：插件的 `ctx.isNaki` 與段位場入口紀錄，不再把遊戲在其他連線送出的同號請求認成 Naki 自送

### 行為變更
- 內部：協定欄位表改由雀魂官方資源包（4.0.47）抽出，與 Akagi 的欄位逐一相同
- 內部：登入回應的錯誤碼改為正確解析，目前沒有畫面使用它

## 已知限制
- 送出守衛「真的擋下請求」沒有 live 驗證：可守衛的方法都是換裝、稱號、領獎類，不對真伺服器測試；目前只有離線測試 → 2026-10-17 狀態：已 live 驗證，L3 關時擋下、L3 開且放行時送出、停用後以 not_on_chain 擋下，各至少 2 次（`docs/archive/notes/known-limits-live-2026-10-17.md`）
- 送出守衛不涵蓋幾種情況，例如退回對局連線的 `sendRaw`、不經 `ctx.replace` 的就地改寫、頁面角色確定前的第一筆 Blob 請求 → 2026-10-17 狀態：修正中（`feat/guard-gaps` 未合併），未 live 驗證
- 整包替換只 live 驗過內容語意不變的重派；改寫顯示值後畫面是否跟著變，未驗證 → 2026-10-17 狀態：等長改寫已 live 看到畫面跟著變；長度不等的整包替換仍未驗證
- `injectReceive` 與 `respondLocally` 尚未實作 → 2026-10-17 狀態：仍未實作
- 對局結束誤報與連線失敗清理的修正只有離線測試，未在 live 重現後驗證 → 2026-10-17 狀態：對局結束誤報已 live 驗證不再出現；連線失敗清理 live 驗證失敗，WebKit 觸發 error 時連線狀態尚未變成已關閉，修正條件不成立，紀錄仍殘留；修正已進 main（fix/ws-error-cleanup），待下一版
- 未簽名：首次開啟要在系統設定放行；IPA 需自行簽名側載 → 2026-10-17 狀態：不變
